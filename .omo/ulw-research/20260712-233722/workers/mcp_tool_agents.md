## Attribution, supersession, and access findings

- Use `scaleapi/mcp-atlas`, not the unofficial `bestwangya/mcp-atlas` fork.
- Use MCPMark Verified for new comparisons; pre-Verified task scores are not comparable.
- Use Toolathlon-Verified for current scoring; retain the older trajectory set only for historical analysis.
- Use Sierra’s τ³ release for current τ-family work. The original `tau-bench` repository explicitly says its tasks are outdated.
- Use MCPVerse’s time-invariant v1.1 file when reproducibility matters; original live tasks have broken dependencies.
- StableToolBench is derived from ToolBench and improves reproducibility; it is not a wholesale rename or deletion of ToolBench.
- CRMArena-Pro supersedes the narrower CRMArena for current enterprise CRM evaluation.
- MCP-Atlas’s 220-versus-307 tool count and MCPWorld’s 201-versus-approximately-170 task count are release-time drift, not necessarily fabrication.
- EnterpriseOps-Gym’s claimed corpus size is not fully represented by the currently exposed HF rows.
- ComplexFuncBench, SOPBench, and EnterpriseOps-Gym each contain internal count inconsistencies that should be preserved as caveats.
- LiveMCP-101, MCP-AgentBench, and AppWorld-UL have credible primary papers but no public standalone code/data release located.
- MCP-RADAR’s only found artifact is an anonymous archive; long-term access is uncertain.
- Toolathlon’s trajectory viewer and card are incomplete, so model/file counts must be read from repository release notes.
- HF access is gated for EnterpriseBench, APIGen-MT-5k, and xLAM-60K; API credentials/accounts are additionally required for many real-server benchmarks.

## Search coverage and dead ends

Representative Exa queries included MCP Atlas, multi-server MCP task datasets, MCP server benchmark trajectories, MCP-RADAR, MCPEval, MCPWorld, LiveMCPBench, MCPMark, MCPVerse, MCP-Persona, LiveMCP-101, MCP-AgentBench, Toolathlon, BFCL V4, ToolBench/ToolAlpaca/API-Bank, τ²/τ³, enterprise MCP environments, customer-service tools, deterministic verifiers, multi-tool trajectories, VAKRA, Live API-Bench, EnterpriseOps-Gym, EnterpriseBench, AppWorld, SOPBench, ECom-Bench, CRMArena-Pro, TRAJECT-Bench, and OrchestrationBench.

Counter-search dead ends:

- No stable organizational repository or HF mirror for MCP-RADAR.
- No release repository found for LiveMCP-101, MCP-AgentBench, or AppWorld-UL.
- No evidence that MCPToolBench++ actually executes 4,000 benchmark servers; primary tables support 87 benchmarked tools.
- No basis to equate VAKRA’s 8,000+ API surface with 8,000 independent benchmark tasks.
- No basis to treat trajectory/training corpora as independent evaluation benchmarks.
- `doganarif/mcp-bench` is a separate small multi-server study, not Accenture’s MCP-Bench and not a replacement for it.
- `exadel-inc/EnterpriseBench` is an unrelated software-engineering/Jira benchmark, not AST-FRI’s enterprise tool-use sandbox.

## CLAIMS

- The strongest currently reproducible MCP-native fixed-task releases are MCP-Atlas, MCPMark Verified, Toolathlon-Verified, LiveMCPBench, MCP-Universe, and MCP-Bench.
- The broadest current tool surfaces are VAKRA/Live API-Bench for locally hosted API universes, ToolBench/StableToolBench for RapidAPI-derived tools, and Toolathlon/EnterpriseOps-Gym for realistic multi-application execution.
- The best stateful customer-tool families are τ³, AppWorld, ToolSandbox, CRMArena-Pro, EnterpriseOps-Gym, ECom-Bench, and the two distinct SOP benchmarks.
- Deterministic or state-based verification is now common in MCPMark, Toolathlon, τ³, AppWorld, ToolSandbox, EnterpriseOps-Gym, VAKRA, and Live API-Bench; pure trajectory matching or LLM judging remains common elsewhere.
- Public availability must be treated separately from paper-scale claims: several 2025–2026 works are paper-only, gated, credential-dependent, or expose fewer rows than advertised.
- Companion logs such as Toolathlon trajectories, MCPMark logs, and APIGen-MT are valuable for trajectory analysis or training but should not be counted as separate benchmark task suites.
